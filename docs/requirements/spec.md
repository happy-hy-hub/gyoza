# 要件仕様書

- プロジェクト: 03.gyoza
- 版: 第2版（2026-09-11 改訂）／ 初版 2026-09-11
- 典拠: `00-charter.md`（**r4**）／ ADR-001〜012（全12件）／ `open-questions.md`
- 改訂理由: 技術調査（V1〜V3）の結果と、それにともなう ADR-012（報知手段の改定）・charter r4（動作要件）を反映
- 本書は決定の**内容**のみを記す。決定の根拠は各 ADR を参照すること。

---

## 目的

1. 餃子を題材に、できるだけ多くのユーザーに、できるだけ長い時間使ってもらう。
   これはソフトウェアの中身の魅力によって達成される事柄であり、非機能要件ではない。受入条件として数値化しない。
2. オンラインに依存せず、ローカル単体で機能が成立する。通信は付加価値に留める。
3. iPhone 実機で日常的に使える形で届ける。

現フェーズはプロトタイプである。評価者は知り合い数名とする。

---

## 非目標

1. 収益化・課金・広告の設計は含めない。
2. サーバ側の恒常運用（アカウント管理・同期基盤・バックエンド運用）は作らない。
3. 餃子以外の料理・ジャンルへの一般化は狙わない。
4. 利用者によるレシピの作成・編集は行わない (ADR-002, ADR-007)。
5. 食べ歩き記録・購入品比較を中心機能としない (ADR-001)。
6. 改善示唆（前回との差分から次の条件を提案する機能）は持たない (ADR-004)。
7. 継続を促す仕掛け（連続記録・回数バッジ等）は持たない (ADR-004)。
8. 不特定多数への公開配布は現フェーズの前提としない。ただし後の広い配布を構造的に閉ざさない。

## スコープ

### 含む

- 主対象ユーザーは餃子を「作る人」。中心利用シーンは家庭での調理手順と記録 (ADR-001)。
- 調理中の手順ガイド。焼き終わりの記録。記録の一覧・振り返り (ADR-002, ADR-004)。
- 同梱レシピの選択 (ADR-007)。
- 記録のエクスポート／インポート (ADR-003, ADR-010)。

### 含まない

- 外部データ源への参照。レシピ DB 連携・店舗情報・価格情報を持たない (ADR-001)。
- 機能としてのオンライン要素。通信はアプリ本体の配信・更新のみとし、これはオンライン機能に数えない (ADR-009)。
- 記録の共有・端末間移送 (ADR-009)。
- レシピの追加取得。レシピの増補は本体更新に同梱して配る (ADR-009)。
- 端末権限の要求。写真・カメラ・通知のいずれも要求しない (ADR-008)。
- 記録一覧からの編集・削除。一覧は読み取り専用とする (ADR-004)。
- **バイブレーションによる報知。iOS Safari で実装不可能である** (ADR-012)。

## 機能要件

### F-1 手順ガイド（中心機能）

- 火加減・蒸し・仕上げを1画面ずつ進める (ADR-002)。
- タイマーを内蔵する (ADR-002)。
- タイマーは**前面表示＋Wake Lock で鳴る**。画面を離れると鳴らない。これは仕様であり不具合ではない (ADR-003)。
- 復帰時に経過時間を再計算し、進行位置を復元する (ADR-003)。

### F-2 報知

- 報知手段は**音**と**満了時の全画面視覚報知**の2つとする (ADR-012)。
- 音は `navigator.audioSession.type = "playback"` を設定する (ADR-012)。
- 音は**ユーザー操作の時点で事前解放する**（`AudioContext.resume()`）(ADR-012)。
- **`AudioContext.resume()` を経ずにタイマーが開始する経路を作らない** (ADR-012)。
- 消音状態の検知は行わない (ADR-012)。
- 調理開始前に「消音では鳴らない可能性がある」旨を**一文だけ表示する。開始前に1回、一文まで**とする (ADR-012)。

### F-3 同梱レシピ

- レシピを複数件アプリに同梱する。利用者はその中から選ぶ (ADR-007)。
- 同梱レシピには、一般的な餃子に加え、作り手の興味をそそる餃子を含める (ADR-007)。
- 初回の利用者に自分の条件を入力させる導線を課さない (ADR-007)。
- 同梱レシピは**版番号付き静的データ**としてコードから分離する。読込をポート化する (ADR-009)。
- レシピデータの版番号は、記録の版番号と独立して扱う (ADR-009)。

### F-4 記録

- 焼き終わりに結果を**1タップで記録**する (ADR-002)。
- 記録は独立機能とせず、**ガイドの終端に組み込む** (ADR-002)。
- 焼き記録1件は次の要素で構成する (ADR-005, ADR-010)。

| 要素 | 内容 |
| --- | --- |
| 不変ローカル ID | 記録の同一性を担保する識別子 (ADR-010) |
| 設定値 | 火加減・焼き時間・水量など、その回のタイマー条件 |
| 日時 | 記録日時 |
| 評価 | 「激うま」／「うま」／「まぁまぁ」の3択。1タップで選択 (ADR-006) |

- 自由メモ（任意テキスト入力）は持たない (ADR-005)。
- 記録は**条件ブロック（版番号付き・入れ子）と評価を分離した構造**とする。フラット列にしない (ADR-005)。
- 記録スキーマに報酬・継続・示唆に類する項目を持たない (ADR-004)。
- 評価3択を提案ロジックへ結線しない (ADR-005)。

### F-5 初期値提示

- 次回起動時に、前回の条件を初期値として提示する (ADR-002)。
- 状態に応じた初期値は次のとおり (ADR-004)。

| 状態 | 初期値 |
| --- | --- |
| 記録あり | 前回値 |
| 記録ゼロ／ストレージ消去後 | 既定値 |
| インポート後 | 復元された値 |

### F-6 記録の一覧・振り返り

- 記録の一覧・振り返りを**読み取り専用**で提供する (ADR-004)。
- 一覧は**独立画面とせず、ガイド終端の記録の延長として配置する** (ADR-004)。

### F-7 エクスポート／インポート

- 用途は**同一利用者の端末内バックアップと復旧**に限定する。他人へ渡す想定は置かない (ADR-009)。
- 形式は**全件一括の1ファイル（JSON）**とする (ADR-010)。
- エクスポートは**端末内の共有シートのみ**を用いる (ADR-005)。
- インポートは**全置換**とする。マージは持たない (ADR-010)。
- 版番号・スキーマの検証に失敗した場合は、**既存データを一切変更しない**（全か無かの置換）(ADR-010)。
- インポート実行前に、**消去される件数を提示する** (ADR-010)。
- 記録の保存後に、**エクスポートを促す導線**を表示する (ADR-010)。

## 非機能要件

### N-1 配信と動作要件

- 配信経路は **PWA**（GitHub Pages 配信・ホーム画面追加）とする (ADR-003, charter 制約2)。
- **動作要件は iOS 18.4 以上とする** (charter 制約6)。
  - Screen Wake Lock API がホーム画面 Web アプリで動作するのは iOS/iPadOS 18.4 以降。
  - `navigator.audioSession` は iOS 17 以降。
  - **18.4 未満の端末は対象外とし、評価者の端末が要件を満たすことを事前に確認する。**
- 追加料金が一切かからないこと。年額課金・従量課金を伴う手段は採用しない (charter 制約4)。
- 有料配布とサイドロードは現フェーズでは採らない (ADR-003)。

### N-2 オフライン

- オンラインに依存せず、ローカル単体で機能が成立する (charter 目的2)。
- 通信はアプリ本体の配信・更新のみに用いる (ADR-009)。

### N-3 データ境界

- **外部送信はゼロ**とする (ADR-005)。
- データはローカル保持を既定とする (charter 制約3)。
- ストレージ消去がありうる前提で設計する (ADR-003)。
- 日時は **UTC 保存・表示時変換**とする (ADR-005)。
- 画像バイナリを保持しない (ADR-008)。

### N-4 権限

- 端末権限を一切要求しない (ADR-008)。
- 報知（音・視覚）は権限を必要としない。**「権限 API 呼出ゼロ」は ADR-012 のもとでも維持される** (ADR-012)。

### N-5 構造

- **タイマー・通知・保存はポートとして抽象化し、Web を一実装に留める** (ADR-003)。
- **報知は音・視覚の2出力を持つ単一ポートとする。ユーザー操作時の `prime()` をポートに定義し、
  `AudioContext` を呼出側へ漏らさない** (ADR-012)。
- **記録は版番号付き条件ブロック構造とする** (ADR-005)。
- **レシピはデータとして分離し、読込をポート化する** (ADR-009)。
- **記録は不変ローカル ID を持つ** (ADR-010)。
- 将来写真を追加する場合は、記録本体の条件ブロック内ではなく**別エンティティへの参照として外付け**する (ADR-008)。

### N-6 検証環境

- 開発は Windows、実働は GitHub 経由、デバッグは iPhone 実機 (charter 制約1)。
- **Windows から Safari 実機デバッガを使用できないため、検証は画面内ログ表示で代替する** (ADR-011)。

## 受入条件

MVP 完了は**必須**と**推奨**の二分で定義する。必須を満たせば MVP 完了とする。推奨は既知の欠落として評価者に伝える (ADR-011)。
これとは別に、**実機チェックリストの必須項目**を設ける (ADR-012)。

### 必須 — 機能条件

| # | 条件 | 検証手段 |
| --- | --- | --- |
| M-1 | 機内モードで、同梱レシピの選択から手順完走・記録までが最初から最後まで通る | 実機手動チェックリスト |
| M-2 | エクスポート／インポートの往復が**全ケースで一致**する（保存値＝再表示値＝エクスポート値） | 値域が有限であることを利用し全ケース検証 |
| M-3 | 版番号・スキーマの検証に失敗したファイルを読み込ませても、既存データが**1件も変化しない** | 不正ファイルを用いた手動検証 |
| M-4 | インポート実行前に、消去される件数が提示される | 実機手動確認 |
| M-5 | **権限 API 呼出がゼロ**である | grep による静的確認＋実機で未要求のまま完走 |
| M-6 | **満了時に画面が規定状態へ遷移する**（全画面の視覚報知）(ADR-012) | 画面 DOM 状態で判定 |
| M-7 | **`AudioContext.resume()` を経ずにタイマーが開始する経路がゼロ**である (ADR-012) | grep による静的確認＋実機で担保 |

### 必須 — 構造条件

| # | 条件 |
| --- | --- |
| M-8 | タイマー・通知・保存がポートとして抽象化されている |
| M-9 | **報知が音・視覚の2出力を持つ単一ポートであり、`prime()` を持つ。`AudioContext` が呼出側へ漏れていない** (ADR-012) |
| M-10 | 記録が版番号付き条件ブロック構造である |
| M-11 | レシピがデータとして分離され、読込がポート化されている |
| M-12 | 記録が不変ローカル ID を持つ |

### 必須 — 同梱レシピ

| # | 条件 |
| --- | --- |
| M-13 | 同梱レシピが**3件**ある。うち**変わり種1件**を含む。**手順数を変える** |

### 実機チェックリストの必須項目

自動検証できないが、満たさなければ MVP 完了としない (ADR-012)。**推奨枠には落とさない。**

| # | 条件 | 検証手段 |
| --- | --- | --- |
| H-1 | **消音スイッチをオンにした状態で、満了音が鳴る** | 実機手動確認 |
| H-2 | 検証端末の iOS が **18.4 以上**である | 設定アプリで確認 |

### 推奨

満たさなくても MVP 完了とするが、既知の欠落として評価者に伝える (ADR-011)。

| # | 条件 | 検証手段 |
| --- | --- | --- |
| R-1 | 前面表示のままタイマーが最後まで鳴り切る | 実機手動確認 |
| R-2 | 画面を離れた場合に鳴らない（仕様として合格扱い） | 実機手動確認 |
| R-3 | 復帰時に経過時間を再計算し、進行位置が復元される | 実機手動確認 |
| R-4 | 初期値が状態に応じて正しい（記録あり→前回値／記録ゼロ・消去後→既定値／インポート後→復元） | 3ケースの手動検証 |
| R-5 | 前回値の残骸が混在しない | 同上 |
| R-6 | 記録0件のときの一覧表示が成立する | 実機手動確認 |
| R-7 | 日時が UTC 保存・表示時変換で扱われ、タイムゾーンをまたいでも記録順が壊れない | 端末のタイムゾーン変更による検証 |
| R-8 | 版番号の異なる記録をインポートしても互換が保たれる | 版違いファイルを用いた検証 |
| R-9 | Service Worker 更新後に、旧版と新版のレシピが混在しない | レシピ版番号を画面表示させて判定 |
| R-10 | レシピデータの版番号が、記録の版番号と独立して扱える | 版違い・レシピ差し替えのインポート往復 |
| R-11 | ストレージ消去後、インポートで全記録が件数・内容ともに一致して復元される | Safari 手動消去で再現 |
| R-12 | 記録の保存後に、エクスポートを促す導線が表示される | 実機手動確認 |
| R-13 | 共有シート・ファイル選択の操作で権限ダイアログが表示されない | 実機手動確認 |
| R-14 | 調理開始前に、消音では鳴らない可能性がある旨が一文だけ表示される (ADR-012) | 実機手動確認 |

**R-4・R-5・R-6（記録一覧と初期値）および R-12（エクスポートを促す導線）は、推奨だが実装順序として優先する** (ADR-011)。

### 保留状態の ADR

**なし。** ADR-001〜012 はすべて状態「採択」である。
うち ADR-002（タイマー要件）と ADR-008（報知手段）は一部改定を受けている（それぞれ ADR-003・ADR-012 による）。
