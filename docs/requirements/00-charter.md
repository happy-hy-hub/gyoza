# 00-charter — プロジェクト憲章

- プロジェクト: 03.gyoza
- テーマ: 餃子に関してのアプリ
- 状態: **承認済み（2026-09-10）／ 改訂 r3（2026-09-10）**
- 起草日: 2026-09-10 / 承認日: 2026-09-10

## 目的

1. 餃子を題材に、**できるだけ多くのユーザーに、できるだけ長い時間**使ってもらう。
   ただしこれは**ソフトウェアの中身の魅力によって達成される事柄**であり、非機能要件ではない。
   受入条件として数値化しない（成功条件3も同様に、指標ではなく「理由が存在すること」を問う）。
2. **オンラインに依存せず、ローカル単体で機能が成立する**こと。通信は付加価値に留める。
3. iPhone 実機で日常的に使える形で届ける。

## 非目標

1. 収益化・課金・広告の設計は今回のスコープに含めない。
2. サーバ側の恒常運用（アカウント管理・同期基盤・バックエンド運用）は作らない。
3. 餃子以外の料理・ジャンルへの一般化は狙わない。

## 制約

1. 開発は Windows、実働は GitHub 経由、デバッグは iPhone 実機。**ローカルに Xcode は無い**。
2. 上記により配信経路は限られる（PWA / Expo EAS / クラウド CI 等）。技術調査で確定させる。
3. オフライン成立が前提のため、**データはローカル保持が既定**。同期は任意機能とする。
4. **追加料金が一切かからないこと。**（r2 で追加）年額課金・従量課金を伴う手段は、
   技術的に優れていても採用しない。無料枠で完結する経路のみを選択肢とする。
5. **現フェーズはプロトタイプであり、評価者は自分の知り合い数名。**（r3 で変更）
   不特定多数への公開配布は現フェーズの前提としない。ただし目的1は最終的に多くのユーザーを見込むため、
   **後の広い配布を構造的に閉ざす選択はしない**こと。少数であっても、各人の端末で無理なく使い続けられる導入方法であること。

## 成功条件

1. 機内モード（完全オフライン）で主要機能が最初から最後まで通ること。
2. 初回起動から中心機能に到達するまで、説明なしで操作できること。
3. 再訪したくなる理由がアプリ内に存在し、それが受入条件として検証可能な形で書けること。

## 改訂履歴

### r3（2026-09-10）— 人間の裁定による。r2 を修正

r2 で目的1を「知り合い数名」に書き換えたのは誤りだった。**目的とフェーズを混同していた**ため、r3 で分離する。

- **目的1を復元し、性質を明記**: 「できるだけ多くのユーザーに長い時間」は最終的に目指すものであり、
  **ソフトウェアの中身の魅力によって達成される事柄**である。非機能要件ではなく、受入条件として数値化しない。
- **制約5を変更**: 「配布対象は知り合い数名」→「**現フェーズはプロトタイプであり、評価者は知り合い数名**」。
  段階の限定であって目的の限定ではない。**後の広い配布を構造的に閉ざす選択はしない**という条件を加える。
- 制約4（追加料金が一切かからないこと）は r2 のまま維持。

**この改訂が既存の決定に与える影響。**

- ADR-001 の未解消リスク「作る人は母数が狭く目的1と衝突する」は、**目的1が復元されたため引き続き有効**。
  Q3（再訪動機）で扱う。ただし現フェーズの受入条件にはしない。
- Q5（配信経路）は、5体中3体が旧目的1を根拠に選択肢 C を退けていた。
  現フェーズの評価者が数名になったことで**その根拠は現フェーズには当たらなくなったため、Q5 は再審議を要する**。
  ただし制約5により「後の広い配布を閉ざさないか」が新たな評価軸として加わる。

### r2（2026-09-10）— r3 により修正済み

- 目的1を「知り合い数名」に変更（**r3 で撤回**）／ 制約4・5を追加。
