# ADR-004: 再訪動機の設計

- 日付: 2026-09-11
- 状態: 採択

## 論点

ADR-002 で決めた「次回起動時に前回条件を初期値提示する」だけで、charter 成功条件3
「再訪したくなる理由がアプリ内に存在し、それが受入条件として検証可能な形で書けること」を満たすか。
足りないなら何を足すか。

## 決定

再訪動機は「前回条件の初期値提示」に加え、**記録の一覧・振り返り（読み取り専用）を足す**。

一覧は**独立画面とせず、ガイド終端の記録の延長として配置する**。
ADR-002 の「記録はガイド終端に組み込む」構造を維持する。

**改善示唆（前回との差分から「次はこうすると良い」を出す）は現フェーズで採らない。**
**継続を促す仕掛け（連続記録・回数バッジ等）は現フェーズで採らない。**

初期値提示の受入条件として、次の3ケースを Q9 に明記する。

| 状態 | 期待する初期値 |
| --- | --- |
| 記録あり | 前回値 |
| 記録ゼロ／ストレージ消去後 | 既定値 |
| インポート後 | 復元された値 |

## 理由

- 人間の裁定による。
- 初期値提示だけでは**蓄積が不可視**である。pm の指摘どおり参照されるのは前回1件のみで、
  検証も「初期値が入る」で終わり、成功条件3 が問う「再訪したくなる理由」としては薄い。
- user-advocate の指摘どおり、初期値提示は**起動後にしか見えず、起動前の人を動かさない**。
  餃子を焼く頻度は人により大きく異なり、月1回程度の利用者が得るのは「前回どうだったか見返せる」利益である。
  また ADR-003 で決めたエクスポートも、中身が見えなければ使い道が伝わらない。
- 実装コストは小さい。architect が明言したとおり、B は ADR-002 で確定済みの**追記型記録への読み取り専用ビュー**であり、
  新たなデータモデルも依存も生まない。増えるのは表示のみである。
- builder は A（何も足さない）を支持したが、その理由は工数であり、かつ builder 自身が最大リスクとして
  「評価者数名から**一度使えば終わりと返り、Q3 を再審議して手戻りする**」を挙げていた。
  B の実装工数と、プロトタイプ評価が空振りして作り直す工数を比べ、前者を採った。
- 一覧を独立画面にしない条件は architect の拒否権（後から剥がせない結合）に対応する。

## 却下した案とその理由

- **A 単独（何も足さない）**: 蓄積が不可視で、再訪動機が前回1件の参照に留まる。上記の理由により不採用。
  ただし A が誤りだったわけではなく、**B は A に足す形**であって初期値提示は維持される。
- **C（前回との差分から改善示唆を出す）**: ADR-002 で「次回提案の正解が定義できず受入条件を書けない」として
  既に却下した論理の再燃である。qa-sec が拒否権を行使した。また architect によれば、示唆ロジックは
  ADR-002 影響範囲の「提案ロジックを記録スキーマから分離」に反する結合を生む。
- **D（連続記録・回数バッジ等の継続を促す仕掛け）**: qa-sec が拒否権を行使。ストレージ消去とタイムゾーンにより
  「連続」の定義が非決定的になり受入条件が書けない。architect も、報酬・継続セマンティクスを記録エンティティに
  埋め込むと ADR-003 のエクスポート／インポート往復に波及する剥がせない結合になると指摘した。
  pm は目的1への寄与が間接的で優先度が低いとした。
- **B を独立画面として実装する案**: ADR-002 の「記録はガイド終端に組み込む」構造が崩れる（architect の条件）。

## 影響範囲

- **Q9（MVP 完了定義）**: 受入条件に上記3ケース（記録あり／記録ゼロ・消去後／インポート後）を明記する。
  qa-sec の指摘どおり、**フォールバック時に前回値の残骸が混在しないこと**を条件に含める。
  一覧については「記録が0件のときに何を表示するか」も受入条件に含める。
- **Q7（初回起動の導線）**: 記録0件の状態が初回利用時の既定状態である。
  user-advocate・pm が挙げたリスク（一覧が空疎に見える／ログ羅列に留まる）は、この空状態の設計で扱う。
- **Q4（ローカルデータ範囲）**: 一覧は読み取り専用ビューであり、新たな保持データを増やさない。
  記録スキーマに報酬・継続・示唆に類する項目を**追加しない**（C・D 不採用の帰結）。
- **C・D の将来的な採用**: qa-sec の拒否権が立っているため、再浮上させる場合は
  受入条件を書けることを示したうえで、改めて争点として審議する必要がある。
- 一覧は**読み取り専用**である。一覧からの記録の編集・削除は本 ADR の決定に含まれない（必要なら別論点）。
