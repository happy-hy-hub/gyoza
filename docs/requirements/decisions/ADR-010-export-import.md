# ADR-010: エクスポート／インポートの形式と挙動

- 日付: 2026-09-11
- 状態: 採択

## 論点

エクスポート／インポートの形式・粒度・インポート時の挙動・操作 UX をどうするか。
ADR-003 で「実装すること」、ADR-005 で「端末内の共有シートのみ」、
ADR-009 で「用途は同一利用者の端末内バックアップと復旧に限定」が既に決まっている。

## 決定

**形式は全件一括の1ファイル（JSON）とする。**

**インポートは全置換とする。マージは現フェーズでは持たない。**

ただし将来のマージ移行を閉ざさないため、次を定める。

- **記録には不変ローカル ID を先に持たせる。**
- **マージの採用には新規 ADR を要する。**

事故予防として、次を受入条件とする。

- **版番号・スキーマの検証に失敗した場合は、既存データを一切変更しない**（全か無かの置換）。
- **インポート実行前に、消去される件数を提示する。**
- **記録の保存後に、エクスポートを促す導線を設ける。**

## 理由

- 人間の裁定による。5体中4体が A（全置換）を支持した。
- 用途はバックアップと復旧に限定済みであり、**復旧は全件を戻せれば目的を満たす**（pm）。
  マージや選択的エクスポートは複数端末併用や他人への受け渡しを前提とするが、その想定は ADR-009 で置かれていない。
- 全置換であれば、ADR-005 の値域有限性により「書いた＝読んだ」で往復検証が済む（builder）。
- **事故予防の条件を付けたのは、A を推した4体全員が同じものを最大リスクに挙げたためである。**
  pm「誤インポートで現行記録が全消失」、architect「全置換が既存記録を消す事故」、
  builder「全置換で既存記録を消す事故」、qa-sec「検証を通った改竄ファイルで全置換され復旧不能になる」。
  立場は A で一致していたが、危険の所在については B を推した user-advocate と完全に同意していた。
  したがって条件なしの A は採らない。
- **user-advocate が B を求めた実質的な理由はマージそのものではなく事故の予防**であった。
  すなわち「ストレージ消去後に焼いた記録を、古いバックアップの取り込みで消してしまう」事故である。
  これは qa-sec の「消去件数の事前提示」と、user-advocate 自身が必須条件とした「促す導線」により
  A のまま対処できる。
- **不変ローカル ID の先出しは architect の条件による。** これは qa-sec の拒否根拠
  「記録に不変 ID がなく、同条件の再焼きと重複を区別できないためマージ判定が非決定的」を、
  将来に向けて解消する。**今はマージを持たないが、持てる状態にしておく**という形である。
- エクスポートを促す導線が要るのは、この機能が「Safari のストレージが勝手に消える」という
  **利用者から予測できない事象への備え**であり、**消えてから初めて必要になる**ためである（user-advocate）。
  導線がなければ、機能があっても使われず手遅れになる。これは A・B どちらを採っても当てはまる。

## 却下した案とその理由

- **B（全件一括／マージ）**: qa-sec が拒否権を行使。記録に不変 ID がなく、**同条件の再焼きと重複を区別できない**ため
  マージ判定が非決定的で受入条件を書けない。ADR-005 の値域有限による全ケース往復検証も崩れる。
  architect は、マージの同一性判定と衝突解決を記録スキーマへ入れることは
  **ADR-009 が剥がせない結合として退けた同期 ID と同型**であり、条件＋日時による判定は
  ADR-005 の入れ子の版が上がるたびに壊れると指摘した。builder は B・C なら反対とした。
  ただし **user-advocate が B を求めた理由（事故予防）は失当ではなく、上記の条件として採り入れた。**
- **C（選択的エクスポート／マージ）**: 5体全員が退けた。普段使わない機能に期間選択の判断を課す（user-advocate）、
  部分ファイルは ADR-003 の往復全件検証を崩す（architect）、選択 UI の工数が
  ADR-007 のレシピ執筆未見積りの現状では収まらない（builder）。
- **条件を付けない素の全置換**: 上記のとおり5体全員が事故を最大リスクに挙げたため採らない。

## 影響範囲

- **ADR-005 の記録スキーマに不変ローカル ID を追加する。** これは ADR-005 が禁じた
  「報酬・継続・示唆に類する項目」には当たらず、同一性の担保のみを目的とする。
  版番号付き条件ブロック構造の外側、記録エンティティの識別子として持つ。
- **Q9（MVP 完了定義）**: 受入条件に以下を追加する。
  - 全件エクスポート → ストレージ消去 → インポートで、**全記録が件数・内容ともに一致して復元されること**
  - **版番号・スキーマの検証に失敗したファイルを読み込ませても、既存データが1件も変化しないこと**
  - インポート実行前に、消去される件数が提示されること
  - 記録の保存後に、エクスポートを促す導線が表示されること
  - 共有シート・ファイル選択の操作で**権限ダイアログが表示されないこと**（ADR-008 の受入条件との整合確認）
- **実装方針**: iOS Safari の PWA では Blob 共有＋file input で実装する（builder）。
- **将来マージを採用する場合**: 不変ローカル ID を同一性判定の基準とし、衝突解決規則を受入条件に含めたうえで、
  **新規 ADR を要する。**
- **持ち越した懸念**: user-advocate が最大リスクに挙げた「**促しが煩わしく無視され、
  結局未実施のまま全記録を失う**」は解消していない。促す頻度と表現の設計は実装時に扱い、
  プロトタイプ評価で煩わしさの有無を観察する。
