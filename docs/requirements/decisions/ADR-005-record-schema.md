# ADR-005: 焼き記録のデータ範囲と境界

- 日付: 2026-09-11
- 状態: 採択

## 論点

ADR-002 で保持対象を「手順定義（静的）」と「焼き記録（追記型）」の2種に定めた。
そのうち**焼き記録1件に何を保持するか**、および保持しないものの境界を決める。
なお「記録に写真を含めるか」は Q10（端末権限）の論点であり、本 ADR では扱わない。

## 決定

焼き記録1件は次の3要素で構成する。

| 要素 | 内容 |
| --- | --- |
| 設定値 | 火加減・焼き時間・水量など、その回のタイマー条件 |
| 日時 | 記録日時 |
| 評価 | 結果の主観評価。**3択**（1タップで選択） |

**自由メモ（任意テキスト入力）は持たない。**

構造と境界について、以下を定める。

- 記録は**条件ブロック（版番号付き・入れ子）と評価を分離した構造**とする。**フラット列にしない。**
- **評価3択を提案ロジックへ結線しない。**
- **外部送信はゼロ。** エクスポートは**端末内の共有シートのみ**とする。
- **日時は UTC 保存・表示時変換**とする。

## 理由

- 人間の裁定による。5体全員が B（設定値＋日時＋3択評価）で立場一致し、反対はなかった。
- ADR-004 で記録の一覧・振り返りを再訪動機に据えた以上、**条件値だけの羅列では「どれが良かったか」が読めない**。
  pm・user-advocate がともに指摘したとおり、A（設定値と日時のみ）では全記録が同じ顔で並び、
  一覧の利益が消えて成功条件3 に寄与しない。
- 3択は enum 1列・1タップで実装工数がほぼゼロであり、ADR-002 の「1タップ記録」を壊さない（builder）。
  台所で手が汚れた状態でも操作できる（user-advocate）。
- 条件ブロックを版番号付きの入れ子にするのは、ADR-002 影響範囲「将来 C（餡・皮）追加で全面改訂としない」を
  満たすためである。フラット列では餡・皮の追加時にインポート互換が壊れる（architect）。
- 評価を提案ロジックへ結線しない条件は、pm と qa-sec が独立に挙げた。qa-sec は最大リスクとして
  「**評価3択が後から示唆ロジック（ADR-004 で却下した C）の入力として再利用され、拒否根拠が迂回される**」ことを
  指摘している。本 ADR はその迂回を明示的に禁じる。
- 値域が有限であることにより、「保存値＝再表示値＝エクスポート値」の往復（ADR-003 の受入条件）を
  厳密に検証できる（qa-sec）。

## 却下した案とその理由

- **A（設定値と日時のみ）**: 一覧を見返しても全記録が同じ顔で並び、「どの条件が良かったか」が読めない。
  ADR-004 で足した振り返りの利益が消える。5体中支持ゼロ。
- **C（自由メモを持つ案）**: 3体が独立に退けた。
  - qa-sec: 長さ・改行・絵文字・XSS と、書き込まれる個人情報の境界が定義できず**受入条件が書けない**（拒否権該当）。
  - builder: 入力 UI・IME・長文表示・エクスポート往復検証が増え、プロトタイプ工数に見合わない。
  - user-advocate: 台所で手が汚れた状態ではテキストを打てず、空欄が並ぶだけになる。
  - architect: 意味が未定義のまま解釈依存を生み、後から剥がせない。
  - pm: ADR-002 の1タップ記録を崩し、現フェーズの優先度にない。
- **記録をフラットな列構造にする案**: 餡・皮などの将来追加でインポート互換が壊れる（architect）。
- **エクスポートをネットワーク経由の共有とする案**: 外部送信は charter 目的2・非目標2 と衝突する。端末内に限定する。

## 影響範囲

- **Q10（端末権限）**: 本 ADR は写真を扱っていない。記録に写真を含めるかは Q10 で決める。
  含める場合、本 ADR の3要素構成と条件ブロック構造への追加として扱う。
- **Q8（エクスポート／インポートの形式・粒度・UX）**: エクスポート先は**端末内の共有シートのみ**に確定した。
  形式は版番号付き条件ブロックを往復できるものであること。残る論点は形式の具体・粒度・操作 UX。
- **Q6（オンライン機能の境界）**: 外部送信ゼロが本 ADR で確定した。Q6 で検討できる「付加価値」から、
  記録データの送信を伴うものは除外される。
- **Q9（MVP 完了定義）**: 受入条件に以下を追加する。
  - 保存値＝再表示値＝エクスポート値が往復で一致すること（値域が有限であることを利用して全ケース検証する）
  - 日時が UTC 保存・表示時変換で正しく扱われること（タイムゾーンをまたいでも記録順が壊れないこと）
  - 版番号の異なる記録をインポートしても互換が保たれること
- **実装方針**: 評価3択は独立フィールドとし、提案ロジックの入力に使わない。
  将来これを示唆ロジックに結線する変更は、ADR-004 の C 不採用の迂回に当たるため、**新規 ADR を要する**。
- **3択の語彙は本 ADR では決まっていない。** 「良かった／普通／失敗」は会議での例示であり、決定ではない。
  Q11 として切り出す。
