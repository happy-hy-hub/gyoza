# ADR-012: 報知手段（ADR-008 の再審議）

- 日付: 2026-09-11
- 状態: 採択
- 改定対象: ADR-008（報知手段の記述を改定する）
- 契機: [docs/research/v1-v3-findings.md](../../research/v1-v3-findings.md) の V3

## 論点

ADR-008 は「報知は音とバイブのみとする」と決めた。技術調査（V3）により
**`navigator.vibrate()` は Safari・iOS Safari とも全バージョンで未対応であり、バイブは実装できない**ことが判明した。
音だけで中心機能（ADR-002 の調理中の手順ガイド）が成立するか、成立させるには何が要るかを決める。

## 決定

**報知は「音」と「満了時の全画面視覚報知」の2つとする。バイブは削除する。**

### 構造

- **報知は音・視覚の2出力を持つ単一ポートとする。**
- **ユーザー操作時の `prime()` をポートに定義し、`AudioContext` を呼出側へ漏らさない。**

### 音

- **`navigator.audioSession.type = "playback"` を設定する**（消音スイッチ下でも鳴らすため）。
- **ユーザー操作の時点で事前解放する**（`AudioContext.resume()`）。
- **`AudioContext.resume()` を経ずにタイマーが開始する経路がゼロであること**を、
  静的確認と実機の両方で担保する。

### 消音への対応

- **消音状態の検知は Web で不可能なため行わない。**
- 調理開始前に「消音では鳴らない可能性がある」旨を**一文だけ表示する**。
  **開始前に1回、一文まで**とする。これを超える説明を置かない。

### 受入条件

- **MVP 必須**: 満了時に**画面が規定状態へ遷移すること**。
- **音が鳴ること**は、ADR-011 の推奨枠には落とさず、**実機チェックリストの必須項目として別立てする。**

## 理由

- 人間の裁定による。
- **A（音のみ）と D（タイマーを中心機能から外す）は5体全員が退けた。**
  音だけでは満了に気づけない状況があり、D は ADR-002・003・011 の作り直しで最大工数、かつ目的1を失う。
- 視覚報知の追加負担はほぼゼロである。ADR-003 により Wake Lock で画面は点いたままであり、
  builder の見積りでは「点灯済み画面の色・大表示切替のみで CSS ＋状態1個、工数差は無視できる」。
- architect の指摘により、音のみの構成は**単一 API への一点依存**になる。
  音・視覚の2出力を単一ポートに束ねることで、ADR-003 のポート抽象化方針と整合する。
- `prime()` をポートに定義する条件は architect による。
  これがないと「UI 各所が AudioContext を直接触り、Web 実装が剥がせなくなる」。
- **一文警告を入れたのは、C を推した2体が求めていたのが検知ではなく静的な一文だったためである。**
  builder は「静的注意文なら B に含む」と明言しており、実質的な対立は一文の要否だけであった。
  pm・user-advocate がともに最大リスクとして「説明過多で成功条件2（説明なしで到達）を損なう」を挙げたため、
  **「開始前に1回、一文まで」という上限を決定に書き込むことで両者の懸念を同時に満たした。**
- **音を実機チェックリストの必須項目として別立てしたのは、qa-sec の指摘への対処である。**
  qa-sec は最大リスクとして「視覚報知が合格条件になり、音が鳴らない実機個体を『仕様どおり』と扱って
  気づけない失敗を見逃す」を挙げた。音は自動テストできないため必須の自動受入条件には置けないが、
  ADR-011 の推奨枠に落とすと「既知の欠落として評価者に伝える」扱いになり、
  **音が鳴らないまま評価に出る可能性が制度上生じる**。これを避けるため別立てとした。

## 却下した案とその理由

- **A（音のみ。ADR-008 からバイブを削るだけ）**: 5体中支持ゼロ。
  消音スイッチ・音量ゼロの状況で満了に気づけず、ADR-002 の中心機能が成立しない。
  qa-sec は「音のみでは満了報知の合否が書けない」として明示的に退けた。
- **C（消音を検知して警告する案）**: **Web に消音状態の検知 API が存在せず、実装不可能。**
  builder・qa-sec が独立に指摘した。検知部分を落とし、静的な一文として採用した。
- **D（タイマーを中心機能から外す）**: ADR-002 を覆し目的1を失う（pm）。
  ADR-002・003・011 の作り直しとなり最大工数（builder）。5体中支持ゼロ。
- **音を ADR-011 の推奨枠に落とす案**（qa-sec の提案の一部）: 推奨枠は「既知の欠落として評価者に伝える」扱いであり、
  音が鳴らないまま評価に出る可能性が生じる。実機チェックリストの必須項目として別立てする形を採った。

## 影響範囲

- **ADR-008 の報知に関する記述を改定する。** 「報知は音とバイブのみ」→「報知は音と満了時の全画面視覚報知」。
  ADR-008 のその他の決定（端末権限を一切要求しない、写真を含めない、通知権限を要求しない）は**無改定**である。
  なお本決定は**新たな端末権限を要求しない**。音も視覚報知も権限を必要としないため、
  ADR-008 の「権限 API 呼出ゼロ」は維持される。
- **spec.md の改訂が必要である。**
  - F-1 の「報知は音とバイブのみとする」を差し替える
  - 必須受入条件に「満了時に画面が規定状態へ遷移すること」を追加する
  - 必須受入条件に「`AudioContext.resume()` を経ずにタイマーが開始する経路がゼロであること」を追加する
  - 非機能要件 N-5（構造）に「報知は音・視覚の2出力を持つ単一ポート。`prime()` を持つ」を追加する
  - 実機チェックリストの必須項目として「消音スイッチをオンにした状態で満了音が鳴ること」を別立てする
- **iOS バージョン制約が生じる。** `navigator.audioSession` は **iOS 17 以降**にしか存在しない。
  V2 由来の「iOS 18.4 以上」と合わせ、**動作要件は iOS 18.4 以上**となる。charter への追記を要する（本 ADR の範囲外）。
- **ADR-011 の必須条件が1つ増える。** 機能条件は5点から、本 ADR 由来の2点を加えて7点になる。
- **ADR-007 との関係**: 事前解放はユーザー操作を起点とするため、
  **レシピを選ぶタップが `prime()` の自然な起点になる。** ADR-007 の導線と整合する。
  ただし「レシピ選択を経ずにタイマーが始まる経路」を作らないこと。
- **持ち越した懸念**: 消音かつ画面を見ていない利用者は、依然として満了に気づけない。
  検知手段が Web に存在しない以上、一文の警告以上の対処はできない。
  **プロトタイプ評価で、消音のまま使う評価者がいたかを観察対象とする。**
