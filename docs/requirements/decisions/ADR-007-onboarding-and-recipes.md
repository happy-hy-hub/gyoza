# ADR-007: 初回導線とレシピの同梱

- 日付: 2026-09-11
- 状態: 採択
- 決定方法: **会議を経ず、人間が直接裁定**

## 論点

初回起動から中心機能に到達するまでの導線をどう設計するか。
ADR-004 により記録0件が初回の既定状態であり、「一覧が空疎に見える」リスクが指摘されていた。

## 決定

**レシピを複数件、アプリに同梱する。** 利用者はその中から選び、**指示どおりに作れば美味しい餃子が作れる**状態にする。

同梱するレシピには、**一般的な餃子だけでなく、作り手の興味をそそる餃子を含める。**

理由は、**餃子を作るという行動と、アプリを初めて操作するという行動が同時期に起きるとストレスになる**ためである。
初回の利用者に「まず自分の条件を入力させる」導線を課さない。

## 理由

- 人間の裁定による。
- 調理という時間制約のある行動の最中に、アプリの初期設定を行わせるのは負荷が高い。
  選ぶだけで始められる状態にすることで、初回の到達が成立する（charter 成功条件2）。
- 記録0件の空状態に対する答えでもある。初回に見えるのは空の記録一覧ではなく、選べるレシピの一覧になる。

## 却下した案とその理由

- **初回に利用者自身の条件入力を求める案**: 調理行動とアプリ操作が重なりストレスになる。上記のとおり却下。
- **一般的な餃子のレシピのみを同梱する案**: 作り手の興味を引く要素がなく、選ぶ楽しみが生まれない。
  変わり種を含めることを必須とする。

## 影響範囲

- **ADR-002 との関係**: 同梱レシピは ADR-002 の保持対象「手順定義（静的）」に該当する。
  単数だった手順定義が**複数になる**。ADR-002 で中心機能から外した「レシピ・配合の作成管理」
  （利用者がレシピを作る機能）とは別物であり、本 ADR はそれを復活させるものではない。
  **利用者によるレシピの作成・編集は引き続きスコープ外。**
- **ADR-001 の未解消リスクを正面から引き受ける。** builder は ADR-001 の会議で
  「レシピ内容の作成が実装外の執筆工数として膨張する」を最大リスクに挙げていた。
  本決定はこのリスクを現実のものとする。**Q9 で工数見積りの対象として明示的に扱うこと。**
  - 見積りに必要な未決事項: **同梱するレシピの件数**、うち変わり種の比率、1件あたりの手順数。
- **Q4／ADR-005 との関係**: 記録の「設定値」は、選んだレシピの条件を初期値として持つことになる。
  記録がどのレシピに紐づくかを保持する必要があるかは、ADR-005 の条件ブロック構造の中で扱う。
  **版番号付き入れ子構造（ADR-005）がこの紐付けを吸収できるかを実装時に確認すること。**
- **ADR-002 の「次回起動時に前回条件を初期値提示」との関係**: 2回目以降の起動では、
  前回条件の初期値提示とレシピ選択のどちらを先に見せるかが導線上の論点になる。
  **本 ADR では決めていない。** 必要なら別論点として立てる。
- **Q9（MVP 完了定義）**: 受入条件に「同梱レシピのいずれかを選び、手順を最後まで通せること」を含める。
