# ADR-008: 端末権限の範囲

- 日付: 2026-09-11
- 状態: 採択

## 論点

端末権限（写真・カメラ・通知）をどこまで使い、拒否された場合どう振る舞うか。
焼き上がりの写真を記録に含めるか。
本論点は ADR-001 の会議で qa-sec が出した条件「写真権限拒否時のフォールバックを受入条件に明記すること」に由来する。

## 決定

**現フェーズは端末権限を一切要求しない。**

- **写真は記録に含めない。** カメラ・写真ライブラリの権限を要求しない。
- **通知権限も要求しない。** ADR-003 によりタイマーは前面表示で鳴るため、通知は仕様上不要である。
- 報知は**音とバイブのみ**とする。

将来写真を追加する場合の構造を、あらかじめ縛る。

- **記録本体の条件ブロック内ではなく、別エンティティへの参照として外付けする。**
- **記録本体と結合させない。**
- **写真の採用には新規 ADR を要する。**

なお本決定により、**権限拒否時のフォールバックという事象自体が現フェーズでは発生しない。**
ADR-001 の qa-sec の条件は、要求する権限がゼロになったことで充足される。

## 理由

- 人間の裁定による。5体中4体が D（現フェーズは権限ゼロ）を支持した。
- 通知については**5体全員が一致**した。ADR-003 でタイマーが「前面表示＋Wake Lock で鳴る」と決まった以上、
  バックグラウンド通知は仕様上不要であり、user-advocate の言うとおり
  「鳴らない通知の権限は利益が説明できない」。
- 写真については qa-sec が拒否権を行使した。根拠は3つあり、いずれも独立している。
  1. 画像バイナリは ADR-005 が依拠する「値域が有限ゆえに往復全ケース検証が成立する」前提を壊す。
  2. **EXIF の位置情報が、ADR-005 の「外部送信ゼロ・共有シートのみ」という漏出境界を定義不能にする。**
  3. ADR-003 のストレージ消去が非決定的で、容量条件が書けない。
- これらを条件化して B を成立させることは可能だが、ADR-007 のレシピ執筆工数がまだ見積もられておらず、
  builder の言うとおり現実的工数に収まらない。プロトタイプの完成を優先した。
- architect が「別エンティティへの参照として外付け」という後付けの型を示しているため、
  **本決定は写真を閉ざさない。** 評価者の反応を見てから追加できる。

## 却下した案とその理由

- **B（写真のみ要求。任意・スキップ可）**: qa-sec が拒否権を行使（受入条件が書けない）。上記3根拠による。
  user-advocate が唯一支持し、「ADR-006 で語彙が全肯定になり一覧は同じ顔で並ぶ。
  ADR-004 の振り返り利益を実際に立たせるのは見た目の差＝写真だけ」と述べた。
  この指摘は却下したが**失当ではない**（下記「影響範囲」に引き継ぐ）。
- **C（写真と通知の両方を要求）**: 通知が仕様上不要であることに加え、B の却下理由がそのまま当たる。
- **記録本体に写真を埋め込む案**: インポート互換が版番号ごと壊れる（architect）。将来も採らない。

## 影響範囲

- **ADR-001 の qa-sec 条件は充足された。** 要求する権限がゼロのため、権限拒否時のフォールバックは発生しない。
- **Q9（MVP 完了定義）**: 受入条件に「**権限ダイアログが一度も表示されないこと**」を含める。
  これは検証可能であり、権限ゼロの決定が実装で守られたことの確認になる。
- **Q8（エクスポート／インポート）**: 画像バイナリが乗らないため、ADR-005 の値域有限性がそのまま保たれる。
  往復検証は全ケース網羅で成立する。形式の選定はこの前提で行ってよい。
- **報知手段**: 音とバイブのみ。Wake Lock で前面表示を保つ前提（ADR-003）と組み合わせて成立させる。
- **持ち越した弱点**: pm と user-advocate が独立に挙げた「**一覧が文字列のみで空疎に見える**」リスクは
  解消していない。ADR-004 で一覧を再訪動機に据えた時点では評価3択が差を作る想定だったが、
  ADR-006 で語彙が全肯定（激うま／うま／まぁまぁ）になり、一覧の差別化力が下がっている。
  **プロトタイプ評価で最優先に確認する項目とする。** ここが弱いと判明した場合、
  写真の追加（新規 ADR）が第一の対処候補になる。
- **将来写真を追加する際の制約**（本 ADR で先に縛った）:
  - 別エンティティへの参照として外付けし、記録本体と結合させない
  - EXIF の除去、容量上限、往復検証の成立条件を受入条件に含めること（qa-sec の3根拠への対応）
  - 新規 ADR を要する
