# ADR-006: 評価3択の語彙

- 日付: 2026-09-11
- 状態: 採択
- 決定方法: **会議を経ず、人間が直接裁定**

## 論点

ADR-005 で焼き記録に「結果の主観評価3択」を持つと決めたが、**語彙は未決**だった。
会議では3体が独立に「死に票化」「評価者ごとに意味が割れ解釈不能」をリスクに挙げていた。

## 決定

評価3択の語彙は **「激うま」／「うま」／「まぁまぁ」** とする。

## 理由

- 人間の裁定による。
- ADR-005 の会議で例示していた「良かった／普通／失敗」は仮置きであり、決定ではなかった。

## 却下した案とその理由

- **「良かった／普通／失敗」**: ADR-005 の会議で用いた例示。採用されなかった。

## 影響範囲

- **3択はすべて肯定寄りの語彙である。** 否定側（失敗・焦げた等）の選択肢を持たない。
  したがって**「うまくいかなかった回」を記録として区別できない**。
  「どの条件が悪かったか」は記録から読み取れず、読み取れるのは「どの条件が特に良かったか」のみになる。
  これは ADR-005 の「評価を提案ロジックへ結線しない」方針とは矛盾しない。
- pm・user-advocate が挙げた**死に票化リスクは解消していない**。語彙が変わっただけで、
  「まぁまぁ」に偏れば一覧の見え方は ADR-005 の A 案（設定値と日時のみ）に近づく。
  プロトタイプの評価時に、この偏りが実際に起きるかを観察対象とする。
- **Q9（MVP 完了定義）**: 3択が enum として保存・再表示・エクスポート往復すること（ADR-005 の受入条件）に、
  この3語彙を当てはめて検証する。
- 語彙の変更は表示層に閉じる。記録スキーマ上は enum の値であり、変更しても ADR-005 の構造に影響しない。
