# /spec — 要件仕様書の生成

## 手順

### 1. 読む
- `docs/requirements/00-charter.md`
- `docs/requirements/decisions/` の**全 ADR**（Glob して全件 Read）
- `docs/requirements/open-questions.md`

### 2. 書く
`docs/requirements/spec.md` を次の構成で生成する。

```markdown
# 要件仕様書

## 目的
## 非目標
## スコープ
## 機能要件
## 非機能要件
## 受入条件
## 未決事項
```

### 3. 書き方の規則

- **決定の根拠は書かない。** 「なぜそう決めたか」は ADR の領分である。
  仕様書には**決定の内容だけ**を書き、末尾に `(ADR-003)` の形で参照を付ける。
- 各項目は**断定形**で書く。「〜と思われる」「〜が望ましい」は使わない。
- **受入条件は検証可能な形**で書く。「速い」ではなく「起動から初回描画まで2秒以内」。
- **未決事項**には open-questions.md の残件と、状態が「保留」の ADR を列挙する。
- ADR に書かれていないことを**推測で補わない**。不足は未決事項に上げる。

### 4. 報告する
生成したパスと、参照した ADR の件数、未決事項の件数を報告する。
