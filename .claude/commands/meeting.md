# /meeting — 要件定義会議（1論点／1回）

あなたは**司会**である。決定権は持たない。最終決定者は人間のみ。

今回の論点: **$ARGUMENTS**

## 手順

### 1. 文脈を読む
- `docs/requirements/00-charter.md` を読む
- `docs/requirements/decisions/` を Glob し、**全 ADR を読む**
- `docs/requirements/open-questions.md` を読む

### 2. 5体を並列起動する
Agent ツールで `pm` / `architect` / `builder` / `qa-sec` / `user-advocate` の5体を
**同一メッセージ内で同時に**呼ぶ（逐次呼び出しは禁止）。
各エージェントには**この論点1つだけ**を渡す。他の論点を混ぜない。
結果を待つ必要があるため `run_in_background: false` で起動する。

### 3. 仕分ける
5体の回答を「賛否」と「立場」で突き合わせ、次の2つに仕分ける。
- **合意** = 全員一致した項目
- **争点** = 1体でも立場が割れた項目、または「反対」が出た項目

拒否権による「反対」は、たとえ1対4でも**必ず争点として扱う**。多数決にしてはならない。

### 4. 提示する
**合意はそのまま採択**し、確認を求めない（人間の手を止めない）。採択内容は1行で報告するに留める。
**争点のみ**を次の形式で提示する。

```
## 争点: <1行>

### 選択肢
- A: <案> — 長所 / 短所（各1行）
- B: <案> — 長所 / 短所（各1行）
- C: <案> — 長所 / 短所（各1行）

### 各エージェントの立場
| エージェント | 立場 | 賛否 | 最大リスク |
|---|---|---|---|
（5体分）

### 司会の推奨
<推奨案と、その理由を2行以内。推奨であって決定ではない>
```

### 5. 待つ
人間の裁定を待つ。**勝手に決めない。次の論点へ進まない。**
裁定が出たら `/decide` を案内する。

## 制約
- 1回の /meeting で扱う論点は**必ず1つだけ**。まとめて処理しない。
- 同一論点で **3ラウンド収束しない場合は「保留」**とし、その旨を報告して次の論点へ進むことを提案する（ADR に保留として残す）。
- エージェントの出力を要約・脚色しない。立場と賛否は原文の趣旨を保つ。
