# Cowork でアプリ開発を回す

Cowork は Claude Code と同じエージェント基盤で動くが、得意分野が違う。効率の差は「何を渡すか」の振り分けと、渡す前に置いておくコンテキストで決まる。

## 1. 作業の振り分け

| 作業 | 担当 | 理由 |
| --- | --- | --- |
| 要件整理・仕様書・ADR の作成 | **Cowork** | 散らかったメモ・議事録・既存ドキュメントをフォルダごと読ませて統合できる。成果物が docx / xlsx / pptx で出る |
| 実装・リファクタ・テスト実行 | **Claude Code** | 差分管理と反復が前提の作業。Cowork でも実行できるが、コード専用の文脈保持と使用量効率で Code が上 |
| 技術調査・ライブラリ比較・API 仕様の下調べ | **Cowork** | Web 検索＋ブラウザ操作＋サブエージェント並列調査が効く。結果を比較表にして残せる |
| テストデータ・検証ログの生成と集計 | **Cowork** | 数式入りスプレッドシートや外れ値検出まで一気に出せる。実装と切り離せるので並列で走らせられる |
| エラー1件の原因質問・構文確認 | **Chat** | Cowork は 1 タスクの消費が大きい。単発の質問はチャットに逃がすのが最大の節約 |
| README / セットアップ手順 / 図の更新 | **Cowork** | 実装後に `/schedule` へ載せると、ドキュメント腐敗を自動で止められる |

## 2. 効率が上がる順の準備

- [ ] **フォルダー指示を書く** — プロジェクトのルートを接続し、構成・命名規約・使うツール・判断基準を書いておく。毎回の説明が消えるので、ここが一番効く
- [ ] **プロジェクト単位で分ける** — ファイル・指示・メモリが独立するワークスペース。案件をまたぐ文脈汚染を防げる
- [ ] **グローバル指示に自分の前提を置く** — 設定 > Cowork。出力言語、レビューの厳しさ、Windows 環境であることなど、全セッション共通のものだけ
- [ ] **並列にできる粒度で渡す** — 「調査→比較表→草案」のような分割可能な依頼はサブエージェントが同時に走る。逐次依存の指示だと並列性が死ぬ
- [ ] **定型を `/schedule` に載せる** — 週次のログ集計、依存関係の更新確認など。クラウド実行なので PC を開いていなくても動く
- [ ] **関連作業は 1 セッションにまとめる** — セッションを割るほど文脈の再構築コストがかかり、使用量も増える

## 3. 詰まりやすい点

> [!warning] ローカル MCP サーバーを含むプラグインはデスクトップアプリ限定
> Web / モバイルからは動かない。ローカルで MCP を開発しているなら、検証は Desktop 側に固定する。

> [!warning] 「自動」モードは使用量を余分に消費する
> 各アクションを安全性チェックしてから実行するため。実害のある操作を含まない調査・文書作成では「手動」でも十分回る。

> [!info] ローカルファイル・ブラウザを使うタスクは Desktop アプリを開いたままにする
> セッション自体はクラウドだが、PC 上のものへのアクセスはアプリ経由。
